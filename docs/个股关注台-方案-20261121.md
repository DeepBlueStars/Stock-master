# 个股报告 × 复核台 / 报告库 接入方案

> 输入样例：`E:\FeishuDownload\恒瑞医药_20261119.pdf`（24 页，数据日 2026-11-19）
> 前置：`docs/组合体检接入方案-20261121.md`、`docs/复核节点设计-20261121.md`
> 本文只解决一件事：**个股报告怎么进系统，以及关注池在复核台怎么呈现。**
> 原型：`docs/原型-复核台-关注池.html`

---

## 0. 结论先行

1. **报告库不改结构**：现有 `research_report` 已支持 `type=STOCK` + `symbol`，直接存整份 Markdown。
2. **复核台新增一层「关注池」**：报告摘要作为关注档案，挂在关注池 `user_favorites` 的 `favorites[].focus` 上，只存 §10 / §12 / §14 的**摘要结论**，不存原文。不单独建集合。
3. **状态不自动跳**：价格只负责算「还差多少 / 已进入买点」的展示标签；`关注中 → 已触发 → 已建仓` 必须由人（或 OpenClaw 显式调用 MCP）确认。这和现有复核线的设计一致。
4. **监测清单拆成两半**：有明确日期的进 `monitor_event`（监测日历）；没有日期的留在关注档案里做指标看板。
5. **一只票只保留一份关注档案**：按 `user_id + symbol` 唯一，新报告整体覆盖，服务端把变化写进时间线，不堆历史垃圾。

## 1. 现状盘点

| 能力 | 已有 | 本次是否复用 |
| --- | --- | --- |
| 报告库 | `research_report` + `/reports` 左右分栏；已支持组合/行业/个股 | ✅ 原样复用，只加「已在关注池」标记与跳转 |
| 报告写入 | MCP `save_research_report` | ✅ 复用；增一个可选 `summary`，个股报告用投资结论做列表摘要 |
| 价格线 | `review_level`（按 user+symbol 唯一，不依赖持仓） | ✅ 继续管**卖出/复核价位**，不重复存买点 |
| 监测日历 | `monitor_event` + 月历 + 状态勾选 | ✅ 扩展「个股监测」这一类事件 |
| 复核台 | 价格复核线 + 监测日历两段 | ✅ 中间插入第三段「关注池」 |
| 个股现价 | `KlineProvider` 可读任意个股日线 | ✅ 关注股不需要持仓也能算现价与距离 |

缺的只有一块：**关注池的结构化档案**，以及它与报告、日历、持仓之间的连接。

## 2. 边界：谁写什么

```
OpenClaw（分析层）                     StockAI（存储 + 展示层）
─────────────────                     ────────────────────────
整份 Markdown        ──MCP──▶         research_report
§10/§12/§14 摘要      ──MCP──▶         user_favorites.favorites[].focus
带日期的监测项        ──MCP──▶         monitor_event（自动同步）
卖出价位/时间复核     ──MCP──▶         review_level（建仓后再写）
                                      ────────────────────────
                                      页面只读、只算距离、只留痕
                                      不自动下单、不自动改状态
```

三条硬约定：

1. **OpenClaw 不传原文表格**：只传压成短句的结论，原文留在报告库。
2. **系统不重算报告结论**：页面不判断「该不该买」，只展示报告给的计划和距离。
3. **状态只能被显式确认**：价格穿过买点只显示 `已进入买点`，不把 `关注档案的 status` 改成 `TRIGGERED`。

## 3. 报告内容怎么落

以恒瑞这份报告为例：

| 报告章节 | 落到哪 | 保留什么 | 不保留什么 |
| --- | --- | --- | --- |
| 十、买入计划与卖出纪律 | `favorites[].focus.buyPlan` / `sellDiscipline` | 结论（观察/不买）、两档买点、上限仓位、持有期、目标价、证伪条件、止损规则、加仓信号 | 大段估值论证、赔率推导 |
| 十二、监测清单 | `favorites[].focus.monitorItems` + 有日期的同步到 `monitor_event` | 指标名、现值、警戒线、复核动作；有日期的补 `eventDate` | 重复的表头、过长的解释 |
| 十四、综合决策备忘录 | `favorites[].focus.decisionMemo` | 六维结论 + 信心度、空仓/持仓两套建议、卖出/加仓信号、一句话总结 | 大师原话、免责声明 |
| 其余章节 | 报告库 | 整份 Markdown | — |

### 3.1 摘要长度（防止卡片被文字撑爆）

| 字段 | 上限 | 说明 |
| --- | --- | --- |
| `stance` | 20 字 | 如「观察，不买入」 |
| `oneLine` | 60 字 | 报告的一句话结论 |
| 每条买入档 `condition` | 60 字 | 触发条件压成一行 |
| 每条证伪条件 | 50 字 | 超过就拆成两条，不写成段落 |
| 每条监测项 `action` | 30 字 | 只写「看到什么做什么」 |
| 六维 `conclusion` | 70 字 | 先给结论，再给一个数字 |

## 4. 数据模型

### 4.1 关注池里的关注档案（`user_favorites.favorites[].focus`）

不新增集合：关注池本来就是 `user_favorites`，每只股票是 `favorites[]` 的一项，关注档案就挂在这一项的 `focus` 上。

```java
@Document(collection = "user_favorites")
public class UserFavorites {
    @Id String id;
    String userId;
    List<FavoriteStock> favorites;
    LocalDateTime createdAt;
    LocalDateTime updatedAt;
}

class FavoriteStock {
    String stockCode;       // 600276
    String stockName;       // 恒瑞医药
    String market;          // A股
    LocalDateTime addedAt;
    List<String> tags;
    String notes;
    BigDecimal alertPriceHigh;
    BigDecimal alertPriceLow;
    FocusProfile focus;     // 有报告时才有
}

class FocusProfile {
    String symbol;          // 600276
    String stockName;       // 恒瑞医药

    String reportId;        // research_report.id
    LocalDate reportDate;   // 2026-11-19，用报告数据日，不用写入日
    String rating;          // 可选，如 A（信息丰富度）
    String source;          // OPENCLAW / MANUAL

    String status;          // WATCHING / TRIGGERED / HOLDING / PAUSED / DROPPED / CLOSED
    String statusNote;      // 状态原因，放弃/暂停必填
    LocalDateTime statusChangedAt;
    String positionSymbol;  // 已建仓时关联的持仓代码，通常与 symbol 相同

    String stance;          // 观察，不买入
    String oneLine;         // 等价格，不等故事
    String coreThesis;      // 可选：一句话生意定义（建议补充，见 §9）

    BuyPlan buyPlan;
    SellDiscipline sellDiscipline;
    List<MonitorItem> monitorItems;
    DecisionMemo decisionMemo;

    List<TimelineItem> timeline;   // 服务端追加，最多保留 50 条
}
```

```java
class BuyPlan {
    BigDecimal maxBuyPrice;     // 43：以上不追
    Integer maxShares;          // 200
    BigDecimal maxWeightPct;    // 16
    String holdingPeriod;       // 3-5 年
    List<String> rules;         // 执行规则，最多 6 条
    List<BuyTier> tiers;
}

class BuyTier {
    Integer tier;               // 1 / 2
    String label;               // 第一档
    BigDecimal priceLow;        // 42.00
    BigDecimal priceHigh;       // 43.00
    Integer shares;             // 100
    BigDecimal amountLow;       // 4200，可空
    BigDecimal amountHigh;      // 4300，可空
    BigDecimal weightPct;       // 8.3，可空
    String condition;           // 价格到位 + 2026Q4 创新药（扣BD）增速 ≥15%
    String status;              // WAITING / TRIGGERED / DONE / CANCELLED
    String note;
}

class SellDiscipline {
    List<TargetTier> targets;   // 52-56 持有；65 减 1/3；75 再减 1/3；>85 清仓
    List<String> invalidation;  // 基本面证伪条件
    StopRules stops;            // 基本面 / 价格 / 组合 / 系统性下跌例外
    List<String> addSignals;    // 加仓信号
}

class StopRules {
    String fundamental;         // 触发任一证伪条件 → 全部卖出
    String priceStop;           // 无基本面消息跌破成本 -20% 减半，-25% 清仓
    String portfolioStop;       // 占组合 >20% 强制减至 20%
    String systematicException; // 沪深300 同期 >10% 且无个股利空，不触发价格止损
}

class MonitorItem {
    String key;                 // INNOVATION_GROWTH
    String metric;              // 创新药收入（扣 BD）增速
    String currentValue;        // +17.05%
    String threshold;           // 连续 2 季 <10%
    String action;              // 下调估值，暂停加仓
    String previousValue;       // 上一份报告的值，用于显示变化（建议）
    String trend;               // UP / DOWN / FLAT，可空
    LocalDate eventDate;        // 有明确日期的才填，填了自动进日历
    String cadence;             // QUARTERLY / ONCE / EVENT，可空
    String importance;          // HIGH / MEDIUM / LOW
}

class DecisionMemo {
    List<Dimension> dimensions; // 六维
    String emptyPosition;       // 空仓者怎么做
    String holder;              // 持仓者怎么做
    List<String> sellSignals;
    List<String> addSignals;
    String oneLine;
}

class Dimension {
    String name;                // 生意质量（段永平）
    String conclusion;          // 优秀。创新药 64.59%...
    String confidence;          // HIGH / MEDIUM_HIGH / MEDIUM / LOW
}
```

`TimelineItem`：`{ at, type, text }`。类型只保留 `REPORT_UPDATE / STATUS_CHANGE / TIER_TRIGGERED / NOTE`，页面按时间倒序展示最近 5 条。

### 4.2 `monitor_event` 增量

不新增必填字段，只加一个类别常量：

```java
public static final String CATEGORY_STOCK = "个股监测";
```

同步规则：

- 只同步 `eventDate != null` 的 `monitorItems`；
- 事件 `title = 股票名 · 指标名`，`detail = 现值 / 警戒线`，`action = 复核动作`；
- 归属用 `symbol + category=个股监测` 圈定（`user_id` 隔离用户）；
- 覆盖时**只删 PENDING**，`DONE` 保留作为历史；
- 如果某条监测项从新报告里消失，它的 PENDING 事件也一起删掉，避免日历上留下过期提醒。

### 4.3 现价怎么来（与持仓同口径）

关注股**不新增定时器、不在 `favorites[].focus` 里存价格**，完全复用持仓那条链路：

1. 日线由 etf-service 写入：交易日 16:20 与 19:30 两轮，只补关注池（`position` / `trade_plans` / `user_favorites`）；周六 02:00 全量扫一遍。
2. Spring 侧 `KlineProvider.ascending(symbol)` 读库内最新一根日线，取 `close` 作为现价；`ExitOverviewService` 和 `FocusPoolService` 走同一个入口。
3. 因此页面看到的永远是**最近一个交易日收盘价**，盘中不刷新；同一天无论什么时候打开，价格一致。

为此 etf-service 的 `KlineBackfillService.focus_symbols` 不需要新增来源：它已经在读 `user_favorites.favorites[].stock_code`，关注档案挂在关注池上后天然被覆盖。不加的话，关注股只有周六全量才会更新，工作日会停在旧价。

首次加入关注池的票，库内没有历史时 `_incremental_start_date` 会回落到 2000-01-01，当天 16:20 那轮直接把全部历史补齐，之后正常增量。在那之前列表显示「暂无日线」，不报错、不算距离。

### 4.4 与 `review_level` 的分工

| 内容 | 放哪 | 理由 |
| --- | --- | --- |
| 买入档位（42-43、38-39） | `favorites[].focus.buyPlan` | 只在「还没买」时有意义 |
| 卖出目标价（65/75/85） | `favorites[].focus.sellDiscipline` | 先作为纪律展示 |
| 建仓后的卖出线、时间复核 | `review_level` | 与现有决策台/复核线同口径，避免两套真值 |

> 状态变成 `HOLDING` 时，由 OpenClaw 再调一次 `save_review_levels`，把卖出线写进 `review_level`；关注阶段不写，防止同一只票在页面上出现两套价位。

## 5. MCP 接口设计

### 5.1 工具清单

| 工具 | 作用 | 说明 |
| --- | --- | --- |
| `save_research_report` | 存整份 MD | 已有；`type=STOCK`、`symbol=600276`；建议补一个可选 `summary` 参数（服务层已支持，见 §10 P0） |
| `save_focus_stock` | 新增/覆盖关注档案 | 新增；写入关注池这只股票的 `focus`，股票不在池里则自动加入；其余字段（标签/备注/提醒价）不动 |
| `list_focus_stocks` | 列出关注池 | 新增；只返回带关注档案的股票，带现价与距离，便于 OpenClaw 复核 |
| `get_focus_stock` | 读一只票的档案 | 新增；写之前先看，避免覆盖错 |
| `update_focus_stock_status` | 改状态/档位 | 新增；`status` 与 `tier` 二选一或同时 |
| `delete_focus_stock` | 从关注池移除 | 新增；连带删关注档案与待处理的个股监测事件，报告原文不删 |
| `save_review_levels` | 建仓后写卖出线 | 已有，不改 |
| `save_monitor_events` | 补非指标类事件 | 已有；监测项的日期由 `save_focus_stock` 自动同步 |

### 5.3 `list_focus_stocks` 返回


### 5.4 状态更新

```
update_focus_stock_status(
  userId?, symbol,
  status?,     // WATCHING / TRIGGERED / HOLDING / PAUSED / DROPPED / CLOSED
  tier?,       // 1 / 2，配合 tierStatus 使用
  tierStatus?, // TRIGGERED / DONE / CANCELLED
  note?        // 原因，放弃/暂停必填
)
```

服务端行为：校验状态流转合法性 → 更新 → 追加 `timeline`。不合法时返回明确文案，例如「CLOSED 不能直接回到 WATCHING，请先恢复为 PAUSED 或重新导入报告」。

## 6. 关注池状态流转

### 6.1 状态定义

| 状态 | 含义 | 谁改 |
| --- | --- | --- |
| `WATCHING` | 关注中，等价格或等条件 | 默认；放弃后恢复也回到这里 |
| `TRIGGERED` | 买点已触发，等执行 | 人确认，或 OpenClaw 明确调用 |
| `HOLDING` | 已建仓 | 人确认，或买入后 OpenClaw 调用 |
| `PAUSED` | 暂停跟踪（逻辑待验证/暂时不看） | 人，必须写原因 |
| `DROPPED` | 放弃（逻辑破坏/不想买） | 人，必须写原因 |
| `CLOSED` | 已清仓归档 | 人，或持仓清零后 OpenClaw 调用 |

### 6.2 流转图

```
                 ┌──────────── PAUSED ────────────┐
                 │ 恢复                           │ 暂停
                 ▼                                │
  [新建] ──▶ WATCHING ──价格进区间+条件确认──▶ TRIGGERED ──实际买入──▶ HOLDING ──清仓──▶ CLOSED
                 │                                │
                 │ 放弃                           │ 条件失效/价格回升
                 ▼                                ▼
              DROPPED ────重新纳入──────────▶ WATCHING
```

### 6.3 允许的流转

| From → To | 条件 | 副作用 |
| --- | --- | --- |
| WATCHING → TRIGGERED | 现价进入某档区间，且该档 `condition` 人工确认 | 该档 `status=TRIGGERED`；时间线记一条 |
| TRIGGERED → HOLDING | 实际成交 | 该档 `status=DONE`；记录 `positionSymbol`；提示去写 `review_level` |
| TRIGGERED → WATCHING | 条件未成立/价格回升 | 该档回 `WAITING`；时间线记原因 |
| HOLDING → CLOSED | 持仓清零 | 归档，不再出现在默认列表 |
| 任意 → PAUSED / DROPPED | 人工 | 必须填 `note`；PAUSED 保留日历，DROPPED 删除其 PENDING 日历事件 |
| PAUSED → WATCHING | 恢复跟踪 | 重新纳入列表 |
| DROPPED → WATCHING | 重新纳入 | 需要新的 `note`，不覆盖原时间线 |

**不允许**：`DROPPED → TRIGGERED`、`CLOSED → HOLDING`、跳过 `TRIGGERED` 直接 `HOLDING`。这些情况应重新导入一份报告，走一次新的判断。

### 6.4 不落库的派生标签

| 标签 | 判定 | 用途 |
| --- | --- | --- |
| `接近买点` | 现价距第一档上沿 ≤3% | 卡片黄色角标、页头计数 |
| `已进入买点` | 某档 `priceLow ≤ 现价 ≤ priceHigh` | 卡片高亮，不自动改状态 |
| `高于不追价` | 现价 > `maxBuyPrice` | 显示「不追」，避免误操作 |
| `报告过期` | `reportDate` 超过 90 天 | 灰化卡片 + 「该更新报告了」 |

### 6.5 新报告覆盖时

- `favorites[].focus` 整体覆盖 `buyPlan / sellDiscipline / monitorItems / decisionMemo`；
- `status` **保持不变**（除非调用方显式传）；
- 服务端比较新旧档案，把变化写进 `timeline`：`报告更新：第一档 43→42，上限 16%→15%`；
- 如果旧档位已经 `DONE`，新报告里对应档位默认 `WAITING`，但时间线保留「已于某日成交」。

## 7. 监测清单 → 监测日历

### 7.1 拆分规则

| 监测项 | 去处 |
| --- | --- |
| 有 `eventDate`（FDA PDUFA、III 期读出、业绩预告） | `monitorItems` + `monitor_event` |
| 只有 `cadence`（每季度更新） | 只留 `monitorItems`，卡片显示「每季度复核」 |
| 纯财务指标（增速、现金流、净现金） | 只留 `monitorItems`，按报告更新刷新现值 |

### 7.2 日历上的样子

```
04-09  恒瑞医药 · 双艾 FDA PDUFA        [个股监测] 高
       现值 PDUFA 2027-04-09 / 警戒线：再 CRL 或推迟
       → 海外逻辑受损，复核目标价
```

- 类别固定为 `个股监测`，与宏观/财报/并购用同一套颜色区分；
- 事件详情里带股票代码，点击可跳回复核台的关注档案卡；
- 完成状态仍用 `PENDING / DONE / SKIPPED`，与现有日历一致。

### 7.3 去重与过期

- 同一 `symbol + reportId + 类别` 下整体替换，避免重复写入；
- 只删 `PENDING`，`DONE` 留作复盘；
- 同一指标在不同报告里换了日期：以新报告为准，旧 PENDING 删除。

## 8. 页面

### 8.1 复核台结构（三段）

```
复核台
├─ 页头：已到价/已到期 · 下次复核 · 关注池 · 下次事件
├─ ① 价格复核线（现有，不动）
├─ ② 关注池（新增，独立区域）
│   ├─ 统计条：关注中 1 / 接近买点 0 / 已触发 0 / 报告过期 0
│   └─ 宽档案卡（每只票一张，三栏：买入阶梯 / 卖出纪律 / 监测清单）
└─ ③ 监测日历（现有，增加「个股监测」类别）
```

### 8.2 关注池档案卡（信息层级）

```
┌────────────────────────────────────────────────────────────────┐
│ 恒瑞医药  600276  [关注中]              46.88  -1.24%          │
│ 2026-11-19 · 个股深度 · A 级 · OpenClaw · 距上次报告 2 天       │
│ ────────────────────────────────────────────────────────────── │
│ 报告结论：观察，不买入。46.88 对应 33.7x；“等价格，不等故事。”  │
│ ┌──────────────────┬──────────────────┬──────────────────┐    │
│ │ 买入阶梯           │ 卖出纪律           │ 监测清单           │    │
│ │ 第一档 42–43       │ 52–56 持有不追     │ 创新药 +17.1% 正常 │    │
│ │  100 股 · 8.3%     │ 65 减 1/3         │ BD 27.8 亿 正常    │    │
│ │  距上沿 -8.3%      │ 75 再减 1/3       │ 现金流 78.4 亿 正常│    │
│ │ 第二档 38–39       │ >85 清仓          │ 净现金 430 亿 正常 │    │
│ │  100 股 · 7.6%     │ 证伪 7 条          │ 估值 33.7x 正常    │    │
│ │  距上沿 -16.8%     │ 价格止损 -20/-25%  │ 双艾 FDA 04-09 待跟进│  │
│ │ 上限 200 股 / 16%  │ 组合上限 20%       │ 六维 高·高·中·中·高·中高│
│ └──────────────────┴──────────────────┴──────────────────┘    │
│ 11-19 报告入库 · 11-19 建立关注档案        [查看档案][标记触发][放弃]│
└────────────────────────────────────────────────────────────────┘
```

设计取舍：

- **用宽档案卡，不用窄网格**：关注池信息量是持仓卡的 3 倍，窄卡会把证伪条件挤成省略号；宽卡三栏正好对应「买 / 卖 / 盯」三件事。
- **买入阶梯放在第一栏**：关注池唯一要天天看的就是「离买点还有多远」。
- **证伪条件默认只显示条数**：点开抽屉看全文，避免卡片变成报告。
- **六维用点阵不用数字**：信心度是排序信息，不是可计算指标。
- **不显示整段估值论证**：要论证就点「查看档案 → 来源报告」。
- **档案卡与上方持仓卡视觉区分**：持仓卡是窄卡、无底色；关注档案卡是宽档案、有结论横条和底栏，避免两段混在一起。

### 8.3 抽屉（点卡片/查看档案）

右侧 560px，五个页签：

| 页签 | 内容 |
| --- | --- |
| 买入计划 | 两档卡片 + 执行规则 + 上限 + 持有期 |
| 卖出纪律 | 目标价表 + 证伪条件 + 四类止损 |
| 监测清单 | 指标表（现值/警戒线/动作/变化）+ 已排期日期 |
| 决策备忘录 | 六维表 + 空仓/持仓建议 + 卖出/加仓信号 + 一句话 |
| 来源报告 | 报告标题/日期/评级 + 摘要 + 「在报告库打开」 |

抽屉底部固定：`状态：关注中 ▾`、`标记已触发`、`放弃跟踪`。所有改状态的动作都要写 `note`。

### 8.4 报告库联动

- 报告列表的「个股」筛选已存在，不新建页；
- 每份个股报告若存在同名 `favorites[].focus`，标题右侧加 `已在关注池` 小标；
- 报告阅读页右上角加一个 `打开关注档案` 按钮，跳到 `/review?symbol=600276` 并自动打开抽屉；
- 反过来，关注档案抽屉的「来源报告」页签直接链到 `/reports?id=<reportId>`。

### 8.5 空状态

- 没有关注池：`OpenClaw 通过 MCP 写入 favorites[].focus 后，这里会按股票列出买入阶梯。`
- 有关注池但没有报告：`档案缺少来源报告，建议让 OpenClaw 重新跑一次分析。`
- 报告过期：卡片右上角 `报告已 96 天未更新`。

### 9.1 建议做

## 11. 风险与取舍

1. **MCP 传 JSON 字符串容易写错**：沿用现有工具风格，但参数说明里必须给完整示例；服务端对必填字段做校验，失败返回具体字段名。
2. **一只票一份档案**：多份报告只看最新一份的计划，历史结论留在报告库。想看「当时怎么想」去报告库，不在关注档案卡上堆历史。
3. **报告结论会变**：新报告可能从「观察」变成「买入」或「放弃」。`status` 不自动跟随 `stance`，必须显式确认，避免 AI 一次推演直接改掉你的纪律。
4. **价格口径**：关注股现价统一用日线收盘（`KlineProvider`），与复核线、决策台同口径；盘中不刷新，避免「页面说没到、日历说到了」。
5. **卖出线双轨**：关注阶段卖出线只在 `favorites[].focus`；建仓后必须由 OpenClaw 写入 `review_level`，否则决策台看不到。这一条要写进 OpenClaw 的接入清单。

## 12. 一句话总结

**报告库负责「原文留档」，关注台负责「现在离买点还有多远、逻辑有没有坏」。** 买入档位、卖出纪律、监测项、决策备忘录各归其位；日历只收有日期的事，状态只由人确认。这样一只票从「看到报告」到「建仓」再到「清仓」，在系统里是一条连续的线，而不是三份互不相干的文档。

## 0. 结论先行

1. **报告的价格线，适合当"复核触发器"，不适合当"卖出参数"。** 它给的是目标价和风险位，不是可执行的交易规则；系统 里已有的 L1/L2/L4 引擎才是执行层。
2. **三只票里只有东鹏的价位设计勉强对称（1.66:1）**，分众的价格线是"止盈近、止损远"（0.5:1），照着执行等于截断利润、放大亏损——这恰恰是报告自己在 §7.1 警告的行为。
3. **"东鹏 -20% 硬止损"在统计上几乎必然被触发**：40.1% 年化波动 → 月 σ≈11.6%，-20% 只有 -1.7σ，正常年份摸到的概率约四成。它不是风险控制，是把波动当成错误。
4. 真正的解法是你已经想到的那件事：**把"什么时候必须重新判断"独立成一层**，止盈止损引擎不动，报告的价值落在"复核节点"上。

## 2. 两个定量问题（这才是"严不严谨"的关键）

### 2.1 赔率

按当前价、报告线机械执行：

| | 现价 | 止盈1 | 上行 | 硬止损 | 下行 | 赔率 |
|---|---|---|---|---|---|---|
| 东鹏 | 113.55 | 160 | +40.9% | 85.64 | -24.6% | **1.66 : 1** |
| 分众 | 5.53 | 6.20 | +12.1% | 4.19 | -24.2% | **0.50 : 1** |

分众 0.5:1 意味着需要 67% 的胜率才不亏——这不是"止损位设置"，这是"负期望结构"。报告没算这一步，是它最大的漏洞。

### 2.2 硬止损的触发概率

东鹏年化波动 40.1%（报告自己给的数）→ 月 σ ≈ 40.1%/√12 ≈ 11.6%。

| 止损 | 相当于 | 单月触发概率 | 一年内至少触发一次 |
|---|---|---|---|
| -20%（报告） | -1.73σ | ~4.2% | **~40%** |
| -25%（系统默认） | -2.16σ | ~1.5% | ~17% |
| -30%（ATR 放宽） | -2.59σ | ~0.5% | ~6% |

东鹏历史上最大回撤 -52%。用 -20% 做硬止损，过去两年里会被打掉多次，然后看着它反弹。**止损位的分母应该是波动率，不是成本。**

### 2.3 但你的处境其实不需要紧止损

东鹏只占总资产 22.46%。东鹏单独 -40%，总资产只 -8.98%（报告压力测试）。也就是说：**这笔仓位的风险已经由仓位大小控制住了，再用 -20% 价格止损，是在同一个风险上收两次费。**

真正的风险是"论文错了还一直拿着"，不是"跌了 20%"。

## 3. 报告内部自相矛盾的三处

1. **§7.1 说"估值止盈：预期回报 < 现金+3% 才减仓"，§7.2 又给了固定价 160/180。** 前者是动态机会成本，后者是静态目标价，两者会在同一只票上给出相反动作。
2. **红利"止盈1 1.60（股息率≈3.8%）"与论文止损"指数股息率<4.0%"几乎同时触发**，一个说减仓、一个说清仓。
3. **"论文止损优先于价格止损"是对的，但 §7.3 的组合触发器全是价格/比例。** 说不清"论文破了但价格没破"时该听谁的。

> 这三处不是挑刺——它们说明报告是**一次性的叙事推演**，不是可执行规则集。用它之前必须做一次"规则冲突消解"。

## 4. 分工：引擎管执行，复核管判断

```
┌─────────────────────────────────────────────┐
│ 判断层：复核节点（新增）                      │
│  到点 / 触线 → "上次的判断还成立吗？"          │
│  产出：维持 / 减仓 / 清仓 / 改参数 / 加仓      │
└───────────────┬─────────────────────────────┘
                │ 复核结论可以修改策略参数
┌───────────────▼─────────────────────────────┐
│ 执行层：ExitRuleEngine（已有，不改参数）       │
│  L1 硬止损 -25%（ATR 放宽到 -30%）             │
│  L2 移动止盈 30%/15%，保本 +10% 兜底           │
│  L4 两档止盈（受 100 股整手约束，见 §11）      │
└─────────────────────────────────────────────┘
```

- 报告价位 → 判断层的条件（`close <= 99.33` 或 `跌破 60 日低点`），**不写进 `PositionExitPolicy.takeProfit1Return`**。
- 引擎参数维持系统现在的值。理由：它是可回测、可解释、和整手约束对齐的；报告那套是叙事。
- 唯一例外：**东鹏 100 股不能分批**，所以它的两档止盈必须合并成"到价清仓或不动"。这是执行约束，不是策略分歧。

## 5. 复核节点是什么

**一句话：一个到点必须回答的问题，回答完要留痕。**

不是"待办事项"（todo 可以不做），也不是"卖出信号"（信号是引擎的活）。它的判据是：

- 有**明确的到期日**或**明确的触发条件**；
- 到期时必须回答一个**具体问题**（"Q4 合同负债是否转负？"而不是"看看东鹏"）；
- 回答后必须选一个**结论**，结论会改变下一次复核的时间或策略参数。

三种类型：

| 类型 | 例子 | 评估方式 |
|---|---|---|
| `TIME` 时间型 | 2027-01-31 东鹏业绩预告 | 到期日比较 |
| `CONDITION` 条件型 | 收盘 ≤ 99.33；组合回撤 ≥20%；现金比 >65% | 每日收盘后算指标 |
| `CADENCE` 定期型 | 每季度财报后 3 个交易日复核论文；每月末复核现金分层 | 上一次完成日 + 周期 |

## 6. 数据模型

```java
@Document(collection = "review_checkpoint")
@CompoundIndex(name = "idx_user_status_due", def = "{'user_id':1,'status':1,'due_date':1}")
public class ReviewCheckpoint {
    String  id;
    String  userId;

    String  scope;       // POSITION / PORTFOLIO / CASH / MARKET
    String  symbol;      // scope=POSITION 时必填
    String  kind;        // TIME / CONDITION / CADENCE
    String  category;    // EARNINGS / EVENT / PRICE / RISK / STRUCTURE / VALUATION / THESIS

    String  title;       // "东鹏 2026 业绩预告"
    String  question;    // "Q4 营收是否连续 2 季负增长、合同负债是否转负？"
    List<String> checklist; // ["Q4 营收增速","特饮增速","茶饮增速","合同负债","分红率"]

    // 触发
    String  metric;      // CLOSE / DRAWDOWN_FROM_COST / PORTFOLIO_DRAWDOWN /
                         // CASH_WEIGHT / SINGLE_WEIGHT / TOP2_WEIGHT /
                         // EFFECTIVE_BETS / LOW_60D
    String  operator;    // LTE / GTE
    BigDecimal threshold;
    LocalDate dueDate;   // TIME 用
    String  cadence;     // ONCE / MONTHLY / QUARTERLY_AFTER_EARNINGS / WEEKLY

    // 来源与提醒
    String  source;      // "组合体检20261121" / "周报2026-11-21" / "手工"
    String  priority;    // P0 / P1 / P2
    Integer remindDaysBefore; // 默认 7
    String  status;      // PENDING / DUE / ACKED / SNOOZED / DISMISSED
    LocalDate lastRemindDate;
    Integer remindCount;

    // 留痕
    String  conclusion;  // MAINTAIN / REDUCE / CLEAR / ADD / REPARAM
    String  conclusionNote;
    LocalDateTime ackedAt;
    String  nextCheckpointId;  // 定期型完成后自动生成
    LocalDateTime createdAt;
    LocalDateTime updatedAt;
}
```

索引：`(user_id, status, due_date)` 足够；条件型每日全表扫也才几十条。

**为什么不用现有 `notification` 凑合**：通知是"发生过的事"，节点是"还没发生、需要你回答的事"，生命周期完全不同。塞在一起，ack 之后就没法追踪"这条到底复没复核"。

**为什么不做成 `PositionMonitor`**：那个是单档价格规则，属于执行层；复核节点是判断层，一个持仓可以同时挂 4 个节点。

## 7. 指标：能自动算的只有这些

原则：**有数据源的自动评估，没数据源的退化成"到期提醒 + 人工填数"。**

| metric | 数据来源 | 说明 |
|---|---|---|
| `CLOSE` | `StockDailyKline` / `EtfDailyQuotes` | 与引擎同口径（收盘价） |
| `DRAWDOWN_FROM_COST` | 持仓均价 | 例如 -8% |
| `LOW_60D` | 日线 | 替代写死的"52 周低点" |
| `PORTFOLIO_DRAWDOWN` | `portfolio_snapshot` 峰值 | 需要先有快照表 |
| `CASH_WEIGHT` / `SINGLE_WEIGHT` / `TOP2_WEIGHT` | `users.cash` + 持仓市值 | 买卖后要回写现金 |
| `EFFECTIVE_BETS` | 权重 | 口径必须写清（见接入方案 §4.3） |
| 股息率 / PE 分位 / 合同负债 | **没有** | 只做 TIME 节点，人工填数 |

这条原则很重要：**不要把"系统算不出来的东西"伪装成自动提醒**，否则你会开始不信任它。

## 8. 提醒节奏（降噪版）

| 场景 | 时机 | 次数 |
|---|---|---|
| 条件型触发 | 每日 08:35（用前一交易日收盘） | 触发当天 1 次；3 个交易日后仍未处理再 1 次，之后静默 |
| 时间型 | T-7、T-1、T0 | 每档 1 次；遇周末顺延到最近交易日 |
| 定期型 | 到期日当天 | 1 次；完成后自动排下一条 |
| 组合阈值 | 每周六周报后 + 每日 08:35 | 每周最多 1 次 |
| 逾期未处理 | 每 7 天 | 最多 3 次，然后标 `SNOOZED` |

- 全部走 `dedupeKey = checkpoint:<id>:<stage>`，天然不重复。
- 站内默认开；L1 级（组合回撤 >20%、单票 >25%）同时推飞书。
- **周六不再单独提醒**——那天你本来就在做分析，节点清单会直接出现在周报开头。

### 9.3 复核动作（关键：必须留痕）

点"现在复核" → 抽屉三步：

1. **看数据**：列出 checklist 对应字段的当前值（能自动填的填，不能的空着）；
2. **勾选**：论文项逐条 是/否/不确定；
3. **给结论**：维持 / 减仓 / 清仓 / 加仓 / 改参数（改参数会回写 `PositionExitPolicy`）。

结论落库 → 生成时间线："2026-11-21 维持，理由：Q3 合同负债 +42.9%；下次 2027-01-31"。

这条时间线是整套东西最值钱的部分：半年后你能看到"当时为什么这么判断"，而不是只剩一个持仓数字。

## 10. 和周六周报的闭环

你已经有周六的组合分析。建议这样接：

1. **周报输入**：`ReviewService.pendingForReport(userId)` 返回"本周到期 + 逾期未处理"的节点；
2. **周报提示词**：在 `prompts/trade-plan-weekly-report.md` 加一节"必须逐个回答的复核问题"，让 AI 针对每个节点给建议；
3. **周报输出**：AI 的建议**不自动改状态**，只作为 `suggestion` 显示在节点卡片上，你点确认才算复核完成（避免 AI 幻觉直接改你的纪律）；
4. **周报结尾**：生成本周新增的节点（比如"分众并购审核有进展 → 加一条 T+3 复核"）。

这样周六的分析从"生成一份报告"变成"推进一批节点"，闭环才成立。

## 11. 顺带修两个 100 股的 bug（现在就会踩）

读 `ExitRuleEngine.java` 时发现，`lot=100` 的整手约束和"分批"逻辑冲突：

```java
// 第 136 行：减半
int half = Math.max(LOT, roundLot(in.holdingQuantity() / 2));
// 100 股：roundLot(50)=0 → max(100,0)=100 → "减仓 100 股（约一半）" = 清仓

// 第 168-173 行：止盈数量
int qty = (int) Math.floor(original * fraction.doubleValue()); // 100*0.3333=33
qty = roundLot(qty);                                          // → 0
return Math.max(LOT, Math.min(qty, in.holdingQuantity()));     // → 100
```

**后果**：东鹏涨到 139.17（+30%）时，系统会提示"减仓 100 股（第一档）"——直接清仓，和"留 1/3 长期持有"完全相反。移动止盈触发时同理，"减半"变成"清仓"。

另外 `takeProfitQuantity` 两档都用了 `takeProfit1Fraction`，第二档的比例永远不生效。

**修法**（二选一，建议 A）：
- A. 整手不足 2 手时，分批类动作降级为"清仓/不动"，并把 action 文案改成"清仓（不足 1 手无法分批）"；
- B. 允许零股卖出（A 股不支持，只能一次性卖，所以 A 才对）。

| POSITION | 红利 | TIME | 2027-01-25 | Q4 季报折溢价是否 >1% |
| PORTFOLIO | — | CONDITION | `PORTFOLIO_DRAWDOWN` ≥ 15% | 相关性是否抬升、是否仍算 1.5 个赌注 |
| PORTFOLIO | — | CONDITION | `SINGLE_WEIGHT` > 25% | 单票超限，是否减仓或改论文 |
| PORTFOLIO | — | CONDITION | `CASH_WEIGHT` > 65% 或 <45% | 现金分层是否失效 |
| CASH | — | CADENCE | 每月最后交易日 | 三层现金（应急 6×M / 机会 10% / 日常 1×M）是否仍匹配 |

> 东鹏的"复核 99.33"不直接落库，落成 `LOW_60D` 条件——因为 52 周低点会滚动，写死就是给自己埋一个过期提醒。

---

## 14. 一句话总结

**报告给的是"什么时候该重新想"，不是"什么时候该卖"。** 把前者做成复核节点，后者留给已经跑通的引擎，两套东西各归各位；周六的分析从"写报告"变成"回答节点"。这样既不会让 AI 的一次推演覆盖你的纪律，也不会让报告白读。

## 15. 落地情况（2026-11-21 已实现）

设计里的 `review_checkpoint` 在实现时拆成了两张表，理由是"价格线"和"时间点"的生命周期不同：

| 设计 | 实现 | 说明 |
| --- | --- | --- |
| `review_checkpoint`（PRICE / TIME 混存） | `review_level`（价格线 + 时间复核，按 user+symbol 唯一） | 一只票一组线，整体覆盖更新，避免旧价位残留 |
| `monitor_calendar` | `monitor_event` | 日历事件，带 importance/status，支持区间事件（如春节备货） |

- 价格线只用于展示"还差多少 / 已到价"，**不产生 ExitSignal、不下单**；到了线由人去让 OpenClaw 重读论文。
- 时间复核落成 `timeReviews[].question`：到点要回答的问题写在数据里，而不是靠记忆。
- 提醒：当前只做页面强调（着色 + 顶部计数），站内信与飞书按需求关闭。
- 东鹏"复核 99.33"按原设计不落成滚动阈值，落成静态价位 + 复核问题；52 周低点变化时由下一份报告覆盖。

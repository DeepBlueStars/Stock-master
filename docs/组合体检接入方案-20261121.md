# 组合体检报告 × StockAI 接入方案

> 输入：`E:\FeishuDownload\组合体检_20261121.pdf`（27 页，数据日 2026-11-21，价格口径 2026-11-20 收盘）
> 目标：把报告里"需要每天盯"的部分，变成项目里**看得到、算得准、到点会提醒**的东西。
> 结论先行、字段级方案、分期清单都在本文；文末附可直接落库的 seed 数据。

---

## 0. 结论先行

1. **报告 27 页，真正值得系统化的只有 4 类**：8 条价位线、6 条组合触发器、9 个日历事件、11 条论文止损项。压力测试、估值倍数、加仓建议属于"一次性判断"，进系统只会变成噪音。
2. **项目已经有约 70% 的地基**：`ExitRuleEngine` 分层判定 + `ExitSignal` + 每日 17:30 定时 + 站内/飞书双通道。缺的是三件事：
   - 每只票的**报告价位**覆盖默认百分比（现在东鹏止盈会被算成 139.17，不是 160）；
   - **组合层体检**（现金比、集中度、回撤、有效赌注）完全空白；
   - **日历型提醒**（1 月业绩预告、并购审核、指数调样）没有载体。
3. **提醒的关键不是"多一条通知"，而是"每条通知都有到期日和动作"**。现有通知只在打开抽屉时才拉取，且没有去重——这是"提醒了但你没看见 / 看见了三次"的根因。

## 1. 报告内容分类：哪些能交给代码

| 报告内容 | 具体例子 | 代码能判定吗 | 承接方式 | 现状 |
|---|---|---|---|---|
| **A. 价位纪律**（8 条） | 东鹏 160/180、移动止盈 ≥140 回撤 15%、复核 99.33、硬线 85.64；分众 6.20/7.00、≥6.50 回撤 12%、复核 4.64、硬线 4.19；红利 1.60/1.75 | ✅ 能 | `ExitRuleEngine` 扩一档"复核线" + 每只覆盖参数 | 引擎有，参数是全局默认 |
| **B. 论文止损**（5+4+2 条） | 东鹏 Q4 营收连续 2 季<0、特饮跌幅>10%、茶饮增速<30%、分红率<80%、合同负债转负，**任 2 项** | ❌ 不能 | 检查清单 + 到期提醒 + 人工勾选，勾满阈值自动出 L3 信号 | 无 |
| **C. 组合触发器**（6 条） | 单票>25%、东鹏+分众>35%、现金<45% 或>65%、证券回撤>20%、有效赌注<1.5、单票<2% 且 6 个月 | ✅ 能 | 新 `PortfolioHealthService` + 每日快照 | `PortfolioPolicy` 只管市场状态下的资产比例 |
| **D. 日历事件**（9 条） | 12 月 CPI/PPI、中央经济工作会议、中证红利调样、1 月东鹏预告、分众并购审核、春节备货、年报 | ✅ 有日期 | 新 `monitor_event` 表 + T-7/T-1/T0 提醒 | 无 |
| **E. 一次性判断** | 五档压力测试、PE 分位、买 2000 份 515180 的建议 | ⚠️ 半能 | 只做展示，不做提醒 | 无 |

> 判据：**能用一个数字和一条线比较的，交给引擎；需要一个日期触发人去看的，交给日历；需要读财报才能判断的，交给清单。** 三者不要混在一个表里。

## 2. 现状盘点（避免重复造轮子）

| 能力 | 已有的 | 缺口 |
|---|---|---|
| 分层止损 | `ExitRuleEngine` L1 硬止损、L2 移动止盈（武装/锁存/保本锚）、L4 两档止盈 | 只有**比例**参数；`takeProfit1Return` 默认 0.30 → 东鹏算成 139.17，报告要 160（+49.46%）；分众要 +18.21%、红利 +19.18% |
| 状态机 | `PositionExitPolicy` 回写 `trailArmed/trailPeakClose/trailFloorPrice/tp1Done/tp2Done`，不重推 | 无"价格复核线"这一档；ETF 硬止损按波动率分档，**红利想关掉止损关不掉** |
| 信号 | `ExitSignal` L1/L2/L4，TRIGGERED/ACKED/RECOVERED，5 交易日冷却 | 无 L3（复核/论文）；ack 之后没有跟进动作 |
| 每日判定 | `ExitTask` 17:30（交易日） | 只判持仓，不判组合 |
| 通知 | `InAppNotificationSender` 落库 + `FeishuNotificationSender` webhook（`feishu.enabled=false`） | 前端只在打开抽屉时 `fetchNotifications()`，**无轮询、无红点更新**；无 `dedupeKey`；无分级路由 |
| 组合层 | `PortfolioPolicy` 按 BULL/SIDEWAYS/BEAR/RISK 给资产类别目标比例 | 没有现金、集中度、回撤、有效赌注、单票下限 |
| 旧监控 | `PositionMonitor` 单档价格/比例 + `MonitorService` | 与 `PositionExitPolicy` 双轨，应迁移后下线 |
| AI 对话 | `mcp/StockAiMcpTools.java` 7 个 `@Tool`（买卖、持仓、现金） | 没有"我现在该看什么/哪条线快到了" |

### 3.1 `position_exit_policy` 扩字段（存量表，加字段即可）

```java
public static class ThesisItem {
    private String  code;      // 如 Q4_REVENUE
```

### 3.2 `portfolio_snapshot`（新，每日一条）

```java
@Document(collection = "portfolio_snapshot")
@CompoundIndex(name = "uk_user_date", def = "{'user_id':1,'trade_date':1}", unique = true)
public class PortfolioSnapshot {
    String  id;
    String  userId;
    String  tradeDate;        // yyyy-MM-dd
    BigDecimal cash;          // users.cash 当日值
    BigDecimal marketValue;   // Σ 持仓市值
    BigDecimal totalAssets;   // cash + marketValue
    BigDecimal equityWeight;  // marketValue / totalAssets
    BigDecimal peakTotalAssets;// 历史峰值（含当日）
    BigDecimal drawdown;      // totalAssets / peak - 1
    BigDecimal top1Weight;    // 最大单票 / totalAssets
    BigDecimal top2Weight;
    BigDecimal effectiveBets; // 口径见 §4.3
    Integer    healthScore;   // 0-100，触发项扣分
    List<String> triggeredRules; // ["SINGLE_MAX","CASH_LOW"]
    LocalDateTime createdAt;
}
```

用途：回撤只能从**序列**里算，没有这张表就只能拍脑袋。同时它也是"体检分"的历史曲线。

## 4. 计算口径（必须先定，否则页面数字和报告对不上）

### 4.1 基础

```
totalAssets = users.cash + Σ(position.totalQuantity × 最新收盘)
cashWeight  = users.cash / totalAssets
singleWeight= 单票市值 / totalAssets
top2Weight  = 前两大市值之和 / totalAssets
```

现金来自 `users.cash`（`ConfigService.updateCash`、MCP `update_cash_balance` 都能改）。**坑**：买卖后现金不会自动回写，体检页会显示错的比例——P0 必须把"成交后回写现金"补上。

### 4.2 与报告对账

| 指标 | 报告值 | 系统按当前持仓重算 | 说明 |
|---|---|---|---|
| 总资产 | 50,553.94 | 一致 | 18,253 + 32,300.94 |
| 现金比 | 63.89% | 一致 | 23,000/50,553.94 之外的 2,745.55 是超额 |
| 东鹏单票 | 22.46% | 一致 | 11,355/50,553.94 |
| 东鹏+分众 | 33.40% | 一致 | 16,885/50,553.94 |
| 东鹏 25% 触发价 | 约 126.4 元 | **约 130.7 元** | 报告用固定总资产；实时口径下东鹏涨价会同时抬高总资产，解 `100p/(39198.94+100p)=0.25` 得 p=130.66 |

> 这张表说明一件事：**报告是静态快照，项目是实时口径**。页面不要照抄 126.4，否则价格到 128 你还在等 126.4 的复核提醒。

### 4.3 有效赌注：两个口径差很多

- HHI 口径（权重平方和倒数）：`1 / (0.6221² + 0.3030² + 0.0749²) = 2.06`
- 报告写的 **1.48** 用这个公式算不出来，大概率做了**相关性调整**（东鹏/分众 60 日相关 0.52，等于把两个仓位折成一个半）。

**决定**：先实现 HHI 口径并在页面标注"未做相关性调整"，同时在 `PortfolioHealthService` 里留 `effectiveBetsAdjusted`（对相关矩阵做特征值分解，取 `(Σλ)²/Σλ²`）。两者都展示，避免"报告 1.48、页面 2.06"被当成 bug。

### 4.4 组合回撤：两条曲线

1. **回溯曲线**（对齐报告）：用当前权重 × 各标的 243 个交易日收益 + 现金按 1.11% 年化，算出权益曲线，取最大回撤。这条能立刻复现报告里的 -36% / -13%。
2. **真实曲线**：`portfolio_snapshot` 逐日累积，半年后替换回溯曲线。

两条都存，页面默认显示真实曲线，样本不足时回落回溯。

### 4.5 相关性

`CorrelationCalculator`：取 60 个交易日对数收益，算皮尔逊相关系数。用于"东鹏+分众>35% 时复核相关性"这条触发器的详情展示，不直接产生信号。

## 5. 提醒链路

### 5.1 时间轴（交易日）

| 时间 | 任务 | 产出 |
|---|---|---|
| 08:30 | `MonitorCalendarTask` | 今天/未来 7 天到期的事件 → 通知 |
| 17:30 | `ExitTask`（已有） | 持仓 L1/L2/L3/L4 信号 |
| 17:35 | `PortfolioHealthTask`（新） | 快照 + 6 条触发器 + 体检分 |
| 17:40 | `NotifySummaryTask`（新） | 当日未读汇总成一条"今日 3 件事" |
| 周五 18:00 | `WeeklyHealthTask` | 周报：本周触发过什么、处理了没有、下周有什么到期 |

### 5.2 分级路由

| 级别 | 例 | 站内 | 飞书 | 冷却 |
|---|---|---|---|---|
| L1 硬止损 | 东鹏 ≤85.64 | ✅ 置顶红 | ✅ 立即 | 5 交易日 |
| L2 移动止盈 | 东鹏 ≥140 后回撤 15% | ✅ | ✅ | 5 交易日 |
| L3 复核 | 跌破 99.33 / 论文勾满 2 项 | ✅ | ❌（进周报） | 1 次/事件 |
| L4 止盈 | 160 / 180 | ✅ | ✅（可选） | 1 次/档 |
| INFO | 日历事件 T-7/T-1 | ✅ | ❌ | 每档 1 次 |

飞书默认关闭是合理的（`feishu.enabled=false`），建议只把 L1/L2 打开。

### 5.3 去重

`dedupeKey`：
- 价位信号：`<code>:<symbol>:<tradeDate>`（同一天同一只同一类型只发一次）
- 日历：`event:<eventId>:T-7`
- 体检：`health:<ruleCode>:<tradeDate>`

落库前 `findByDedupeKey` 判重；Mongo 唯一稀疏索引兜底。

### 5.4 前端要改的地方

- `App.vue`：`fetchNotifications()` 改为 `setInterval(60_000)` + `visibilitychange` 时刷新；红点用 `unreadCount`；点击通知跳 `n.link`。
- 通知项加"处理"按钮：直接跳到 `/decide?symbol=xxx` 并打开该票的处置抽屉。
- 可选：`Notification.requestPermission()`，L1/L2 走浏览器系统通知（页面没开也能看到）。

### 5.5 降噪原则

- 只在交易日发；收盘前不发价位信号（用前一日收盘判定，和引擎一致）。
- 同一标的同一天最多 2 条（1 条价位 + 1 条日历）。
- 周报只写"有变化"的：新触发、已处理、下周到期。

## 9. 边界与坑

1. **报告数据多处"未核实"**（行情、成本、分红、ETF 净值溢价、公告日期）。系统里这些值应该标来源和更新时间，页面别做成"权威数字"。
2. **价格口径必须统一**：引擎用日线收盘、体检用同一根日线，别一边收盘一边实时，否则会出现"页面说还没到、信号已经触发"——这正是 `ExitOverviewService` 注释里已经踩过的坑。
3. **红利 ETF 的止损必须显式关闭**：`etfHardStopTiers` 会按波动率给 15%，红利年化波动 15.1% 正好落在第一档，不关掉会在 -15% 时误报硬止损，而报告的纪律是"无价格止损，只按股息率/PE 分位"。
4. **论文止损不能自动扣分**：只能做"到期未勾选"的催办。自动化的边界要写在页面上，否则用户会以为系统替他读了财报。
5. **`users.cash` 是手工维护的**：买卖成交后不同步，现金比就全错。P0 顺手补：`StockService.buy/sell` 成功后回写现金（MCP 已有 `update_cash_balance` 可复用）。
6. **`PositionMonitor` 与 `PositionExitPolicy` 双轨**：迁移完就把 `MonitorService`/`MonitorTask` 标 `@Deprecated`，否则同一个止盈会发两条通知。
7. **东鹏 100 股**：所有分批建议都要过 `lot=100` 校验，不足 1 手时降级为"清仓/不动"。

## 11. 落地情况（2026-11-21 已实现）

本阶段按"报告由 OpenClaw 写入、系统只负责看"的边界实现，没有做推送。

### 11.1 报告库（新增）

- 模型 `research_report`：`po/ResearchReport.java`（type / reportDate / periodStart / periodEnd / summary / content(Markdown) / rating / tags / source）。
- 接口 `/research/report/save|list|delete`、`GET /research/report/{id}`，见 `controller/ResearchController.java`。
- MCP：`save_research_report`、`list_research_reports`、`get_research_report`（`mcp/ResearchMcpTools.java`）。
- **OpenClaw 只传整份 Markdown，不传摘要**：报告开头本身就是总结，`ResearchService.deriveSummary` 会跳过标题、引用块、表格和"数据日/价格口径"这类元信息段，取第一段实质正文，到下一个 `#` 标题为止，超过 120 字按句号截断。手工/HTTP 写入仍可显式传 `summary` 覆盖。
- 页面 `/reports`（`components/ReportLibrary.vue`）：左侧按类型筛选的列表，右侧 Markdown 阅读区；渲染器是自写的 `utils/markdown.js`，无新增依赖。

### 11.2 持仓复核线（新增）

- 模型 `review_level`（user + symbol 唯一）：`priceLevels[]`（止盈一/二档、移动止盈、价格复核、硬风险、再平衡）+ `timeReviews[]`（日期 + 复核问题）+ `thesisStops[]`。
- 接口 `/research/review/save|list|delete`；MCP `save_review_levels`、`list_review_levels`、`delete_review_level`。
- 页面 `/review`（`components/ReviewBoard.vue`）：每只票一列"价位阶梯"，按现价算"还差 / 已到价 / 已跌破"；时间复核按"已过 / 今天 / N 天后"着色。
- 关键取舍：**复核线独立于持仓存在** —— 报告给了东鹏 99.33，即使系统里没有东鹏的持仓记录，这条线也要显示，否则"该复核的东西"会被数据缺失吞掉。

### 11.3 监测日历（新增）

- 模型 `monitor_event`：eventDate / endDate / title / category / detail / action / importance / status。
- 接口 `/research/event/save|list|status`；MCP `save_monitor_events`、`list_monitor_events`、`update_monitor_event_status`。
- 页面同上：月历 + 当日事件面板；本月没有安排时自动停在"下一个事件"所在月。
- 事件状态只有待处理 / 已完成 / 已跳过，不触发任何交易动作。

### 11.4 周报去重

- `TradePlanSummaryTask` 改为周六 18:00（`trade-plan.summary-cron: 0 0 18 ? * SAT`）。
- 生成前先查 `hasPortfolioReportSince(userId, 本周一)`：OpenClaw 已传本周组合报告则跳过该系统周报。

### 11.5 明确没做

- 不做系统内提醒、不做飞书推送（按当前需求）；`feishu.enabled` 仍为 false。
- 不做组合层聚合指标（现金比、集中度、有效赌注、回撤）—— 这些仍写在报告正文里，等报告库稳定后再考虑从 `portfolio_snapshot` 计算。
- `ExitRuleEngine` 的整手 bug（100 股时"减半"= 清仓、二档止盈复用一档比例）**未改**，因为它会改变已跑通的卖出纪律，需要单独确认。

# 股票行情数据获取优化计划

## 1. 分析当前实现

* **后端**：定时任务每5秒更新一次行情数据，接口超时时间为30秒

* **前端**：每10秒调用一次后端获取涨停股票数据

* **数据源**：已经集成了tushare、akshare、eastmoney等多个数据源

## 2. 优化方案

### 2.1 后端优化

* **修改定时任务频率**：将 `backend/app/tasks/market_tasks.py` 中的 `update_interval` 从5秒改为60秒

* 后端从第三方接口获取到数据后，将数据存入redis缓存，redis连接方式在`.env`文件

* **调整接口超时时间**：将 `backend/app/routers/market.py` 中的超时时间从30秒改为60秒

* **优化数据源调用**：确保优先使用tushare和akshare等稳定数据源

* 前端调用后端获取涨停股票的接口\`http\://localhost:8000/api/v1/market/limitup\`，数据从redis缓存中获取，不直接通过第三方API，可以减少第三方API的调用频率

### 2.2 前端优化

* **修改刷新频率**：将 `frontend/src/views/market/index.vue` 中的 `setInterval` 从10秒改为60秒

* **添加错误处理**：增加请求失败时的重试机制

### 2.3 数据源稳定性提升

* **优先使用akshare，其次tushare，然后才是其他接口**：这两个数据源在代码中已经设置为高优先级

* **增强故障转移**：确保当主数据源失败时能快速切换到备用数据源

* **添加缓存机制**：合理使用缓存减少对API的频繁调用

## 3. 实施步骤

1. 修改后端定时任务频率
2. 调整接口超时时间
3. 修改前端刷新频率
4. 验证修改效果

## 4. 预期效果

* 降低API调用频率，减少被限流的风险

* 保持数据的实时性（1分钟一次的频率足够满足行情监控需求）

* 提高系统的稳定性和可靠性
